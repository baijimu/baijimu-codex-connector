# Codex Home 所有权与启动流程

## 状态

- 设计状态：已确认
- 实现状态：1.2.39 已实现首次初始化、所有权保护、无合成项目的显式启动主流程和管理令牌启动前置契约
- 适用组件：`baijimu-connector-codex`、Bridge Agent 本地应用启动与升级流程

本文定义 Codex 状态目录的所有权、首次初始化、百积木内启动、外部 Codex 行为以及显式切换规则。实现不得仅依据目录是否存在做覆盖决定，也不得把 Windows 用户环境广播放入 Connector 启动或健康检查路径。

## 目标

1. 首次使用 Codex 的用户无需理解 `CODEX_HOME`，从百积木启动即可使用。
2. 用户没有既有 Codex 状态时，外部 Codex 也可以自然使用百积木初始化的默认状态。
3. 已有 Codex 用户的登录、配置、会话、MCP 和自定义目录不被覆盖。
4. 百积木启动的 Codex 始终使用明确选定的状态目录，不依赖 Explorer、终端或全局环境刷新。
5. Connector 必须在独占回环监听端口后同步创建并回读管理令牌，才能报告启动成功并开始提供 `/healthz`；后续初始化、`/readyz` 不依赖桌面应用、用户环境广播或其他 GUI 进程响应。

## 基本事实

- 未设置 `CODEX_HOME` 时，Codex 使用用户默认目录：
  - Windows：`%USERPROFILE%\.codex`
  - macOS/Linux：`$HOME/.codex`
- 进程环境属于进程自身。Connector 可以在启动 `codex app-server` 时显式传入 `CODEX_HOME`，该值会立即对其子进程生效。
- 写入 Windows `HKCU\Environment` 只是在注册表中持久化用户环境，不会修改已运行进程的环境块。
- `WM_SETTINGCHANGE` 只是通知 Explorer 等程序重新读取用户环境；它不能可靠地更新已经运行的 Codex 或终端。
- 因此，用户环境写入和广播都不是 Connector 可用性的前置条件。

## 权威状态与所有权

Connector 必须分别管理以下三类状态，不得相互推断：

1. 用户显式配置的 `CODEX_HOME`
   - 属于用户。
   - Connector 不得在后台覆盖、删除或改写。
2. 用户默认的 `.codex`
   - 可能不存在、为空、由百积木初始化，或者已经包含用户自己的 Codex 状态。
   - 目录存在本身不能代表已经完成初始化，也不能代表允许覆盖。
3. Connector 私有状态目录
   - 位于 `BAIJIMU_CONNECTOR_DATA_DIR` 下。
   - 用于保存 Connector 元数据、管理令牌和隔离的百积木工作区配置档案。

百积木初始化默认 `.codex` 时必须写入不含秘密的所有权标记。标记至少包含：

- 固定的 schema 版本；
- 所有者标识 `baijimu-connector-codex`；
- 初始化时间；
- Connector 管理的文件清单；
- 不包含用户 ID、工作区 ID、凭证或环境地址。

工作区、用户、环境等可变业务数据必须来自 Connector 凭证元数据和平台授权结果，不得写成运行时分支或固定名单。

## 启动前状态判定

按以下顺序判定，不得只执行 `Test-Path ~/.codex`：

### 1. 用户已经显式设置 `CODEX_HOME`

- 将该路径视为用户所有。
- 不写入、不切换、不广播。
- 百积木使用 Connector 私有的工作区配置档案。
- 从百积木启动 `codex app-server` 时显式传入私有档案路径。

### 2. 用户未设置 `CODEX_HOME`，默认 `.codex` 不存在或确认为空

- 这是首次使用状态。
- 在默认 `.codex` 中初始化百积木凭证和必要配置。
- 写入百积木所有权标记。
- 不设置用户级 `CODEX_HOME`，不广播。
- 从百积木启动时可以显式传入默认 `.codex`，也可以使用 Codex 默认解析；实现应优先显式传入，避免启动父进程环境造成歧义。
- 用户之后从外部启动 Codex，也会自然使用默认 `.codex`。

“确认为空”是指不存在 Codex 登录、配置、会话、状态数据库、MCP 配置或其他无法证明由百积木管理的内容。仅存在空目录或百积木创建过程留下的可验证临时文件时，才可继续初始化。

### 3. 用户未设置 `CODEX_HOME`，默认 `.codex` 有百积木所有权标记

- 校验标记 schema 和管理文件清单。
- 仅更新百积木明确拥有的文件。
- 不覆盖标记之外的用户文件。
- 不设置用户级 `CODEX_HOME`，不广播。

### 4. 用户未设置 `CODEX_HOME`，默认 `.codex` 已有用户状态且无百积木所有权标记

- 将默认 `.codex` 视为用户所有。
- 不修改、不迁移、不合并凭证文件。
- 在 Connector 私有目录中创建隔离的百积木工作区配置档案。
- 从百积木启动 `codex app-server` 时显式传入该私有路径。
- 用户从外部启动 Codex 时继续使用原来的默认 `.codex`。

## 从百积木启动

用户点击 Bridge Agent 中的“启动应用”后：

1. Bridge Agent 启动并托管 Connector 进程。
2. Connector 独占绑定回环地址，但尚不接收 HTTP 请求。
3. Connector 在私有数据目录中加载或原子创建管理令牌，并回读确认文件内容与进程内值一致；失败时直接退出，不得报告启动成功。
4. Connector 报告启动成功并开始提供 `/healthz`，此时 Bridge Agent 必须已经能够读取管理令牌。
5. Connector 加载所有权元数据和当前百积木工作区档案。
6. Connector 根据上述状态判定选择本次使用的 Codex Home。
7. Connector 达到核心可服务状态后，`/readyz` 返回成功。
8. 当会话能力需要 `codex app-server` 时，Connector 以子进程环境显式传入选定的 `CODEX_HOME`。
9. 子进程退出或工作区切换时，由 Connector 回收并按新档案重新启动。

启动流程禁止：

- 写入用户级 `CODEX_HOME`；
- 广播 `WM_SETTINGCHANGE`；
- 等待 Explorer、Codex Desktop、终端或其他 GUI 进程；
- 为了通过健康检查而隐藏凭证、目录或子进程启动错误。

## 切换规则

### 显式启动桌面 Codex

用户在工作区管理页选择个人 Codex 或百积木工作区时，Connector 可以重启官方桌面应用，使新进程读取所选状态目录。该操作必须：

1. 只调用操作系统的标准应用启动入口，不传入文件、目录或项目参数。
2. 立即检查真实桌面进程；尚未注册时按短间隔轮询至总超时，不增加固定启动延时。
3. macOS 回读新进程环境中的 `CODEX_HOME`；Windows 回读用户环境并确认新进程已启动。
4. 不以窗口是否可见、窗口句柄或前台状态推断进程和状态目录正确。
5. 不创建 `~/Documents/Codex/default` 或任何其他合成项目来制造可见窗口。

### 百积木内部切换工作区

- 更新 Connector 自己的活动档案元数据。
- 停止 Connector 托管的 `codex app-server`。
- 使用新档案路径显式设置子进程 `CODEX_HOME` 并重新启动。
- 不修改用户级环境，不广播，不影响外部 Codex。

### 显式切换外部 Codex 默认状态

只有用户明确选择“同时切换外部 Codex”时，才允许修改用户级 `CODEX_HOME`。该操作必须：

1. 精确保存原始状态，区分“未设置”和“自定义路径”。
2. 原子写入并回读校验目标值。
3. 将 Windows 环境通知作为该显式操作的一部分，而不是 Connector 启动的一部分。
4. 使用独立、可取消且有总时限的通知任务；不得阻塞 Connector `/readyz`。
5. 明确提示用户重启已经打开的 Codex 和终端，因为广播不能修改现有进程环境。
6. 恢复时严格还原原始值，不删除任何 Codex 状态目录。

如果产品不提供“同时切换外部 Codex”功能，则用户级环境写入和广播代码应完全删除。

## 文件写入与安全约束

- 凭证必须通过私有临时文件或内存传递，日志、所有权标记和错误信息不得包含密钥。
- `auth.json`、`config.toml` 和所有权标记必须采用同目录临时文件加原子替换。
- Windows 应限制文件 ACL；Unix 应使用仅当前用户可读写的权限。
- 初始化任何一步失败时，不得留下看似完整的所有权标记。
- 只有全部必需文件写入并回读成功后，才能提交所有权标记。
- 已有用户文件不能用默认值整体覆盖；需要修改时必须按已声明的文件和字段所有权合并。

## 健康检查契约

- `/healthz`：进程已存活、管理令牌已落盘且能响应 HTTP，不依赖工作区凭证初始化或桌面状态。
- `/readyz`：Connector 的管理令牌、元数据和核心请求处理已经可用。
- 首次凭证安装、官方 Codex 安装和桌面启动属于可观察的 setup 状态，不得成为 Connector 进程存活的前置条件。
- Windows 环境广播不属于 health 或 readiness。
- Bridge Agent 应记录每次启动尝试、就绪失败正文和进程回收原因，界面必须能够查看完整错误。

## 旧版本迁移

旧版本可能已经把用户级 `CODEX_HOME` 指向 Connector 私有工作区目录。升级实现必须：

1. 读取现有凭证元数据中保存的原始环境状态。
2. 只有能证明当前值由 Connector 设置时，才允许执行恢复。
3. 不在后台启动或健康检查中静默修改用户环境。
4. 将恢复作为一次明确、可审计的迁移操作，并在完成后提示重启外部 Codex/终端。
5. 无法证明所有权时保持现状并提示用户处理，不得猜测或删除。

## 验收矩阵

至少覆盖以下自动化测试和 Windows 真机验证：

| 场景 | 默认 `.codex` | 用户级 `CODEX_HOME` | 百积木使用目录 | 外部 Codex | 广播 |
| --- | --- | --- | --- | --- | --- |
| 全新用户 | 不存在 | 未设置 | 初始化后的默认 `.codex` | 使用百积木初始化状态 | 无 |
| 空目录 | 空 | 未设置 | 初始化后的默认 `.codex` | 使用百积木初始化状态 | 无 |
| 百积木已初始化 | 有有效所有权标记 | 未设置 | 默认 `.codex` | 使用同一默认状态 | 无 |
| 已有 Codex 用户 | 有用户状态、无标记 | 未设置 | Connector 私有档案 | 保持原状态 | 无 |
| 用户自定义 Home | 任意 | 已设置 | Connector 私有档案 | 保持用户自定义状态 | 无 |
| 百积木内部切换 | 任意 | 任意 | 新的 Connector 档案 | 不受影响 | 无 |
| 用户显式切换外部 Codex | 任意 | 用户确认后变更 | 用户选择的档案 | 重启后使用新状态 | 仅该操作触发 |

还必须验证：

- `.codex` 非空但只有未知文件时不会被接管；
- 初始化中断不会留下有效所有权标记；
- 多次启动幂等，不重复签发凭证或重写无关文件；
- 任意 GUI 程序无响应时，Connector 仍能在健康窗口内启动；
- 从百积木启动的 `codex app-server` 实际读取的是所选目录；
- 用户原始 `auth.json`、`config.toml`、会话和 MCP 配置逐字节保持不变。

## 明确禁止的实现

- 仅以 `.codex` 目录是否存在判断是否允许初始化。
- Connector 每次启动都重写用户级 `CODEX_HOME`。
- Connector 每次启动都广播 `WM_SETTINGCHANGE`。
- 把广播失败转换成健康失败、降级兼容分支或无限重试。
- 为了制造可见窗口而创建或打开合成项目、目录或文件。
- 把窗口可见性、前台状态或窗口句柄当成桌面进程与状态目录的验证结果。
- 为特定用户、工作区、环境或机器写固定分支。
- 在无法证明目录所有权时自动覆盖、合并或删除用户 Codex 状态。
